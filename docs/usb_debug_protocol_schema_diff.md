# USB Debug/Test protocol schema diff

## 4.4 -> 4.5

Release 4.5 raises `schema_version` from 3 to 4 and separates the binary
diagnostic connection from ownership of state-changing hardware tests.

- `TEST_SESSION_BEGIN` validates a bounded lease and velocity/current/torque
  ceilings. Motion ownership requires an explicit independent-estop flag.
- `TEST_SESSION_STATUS` reports the session ID, state, lease remaining, applied
  ceilings, and rejection reason.
- `TEST_SESSION_KEEPALIVE` renews the lease. Expiry and physical USB disconnect
  submit DISARM without depending on the host process.
- `TEST_SESSION_STOP` submits a correlated DISARM and returns the normal
  terminal `COMMAND_RESULT`; a motion session cannot END before that result is
  COMPLETED.
- `TEST_SESSION_END` releases clean ownership. Runtime limits are restored only
  on this clean path; timeout/disconnect retain the conservative limits.
- `COMMAND` is rejected unless a Test Session is active. ARM additionally
  requires the motion and hardware-estop flags.

HELLO, framed diagnostics, Scope, calibration records, and Crash Recorder remain
wire-compatible except for the required schema-version byte.

## 4.3 -> 4.4

Release 4.4 raises `schema_version` from 2 to 3 and adds retained crash
reporting without changing the 40-byte frame header:

- `CRASH_REPORT` (16) transports a fixed 204-byte, CRC-protected Cortex-M
  exception record after the HELLO/CAPABILITIES gate.
- `CRASH_ACK` (17) acknowledges the retained record CRC. Firmware clears the
  `.noinit` record only after queuing a matching response.
- CAPABILITIES bit 8 advertises Crash Recorder support.
- The payload carries the crashing build/manifest identity independently from
  the currently running firmware identity, enabling exact old-ELF lookup.

The retained RAM contract survives a Cortex system reset but does not claim
power-loss persistence.

## 4.2 -> 4.3

Release 4.3 changes the CDC transport contract without changing the frame
header or payload schema (`protocol_version=4`, `schema_version=2`):

- CDC is binary-only from configuration onward; legacy `@log` text is not
  multiplexed onto this port.
- The device emits no unsolicited bytes before a valid `HELLO` and responds
  first with `CAPABILITIES`.
- Firmware CDC submissions are capped at 63 bytes. Protocol frames remain an
  arbitrary byte stream and may span USB packets; the cap avoids the customized
  STM32 CDC driver's full-packet/ZLP completion state.

The remainder of this document records the earlier 4.1 -> 4.2 schema changes.

Phase 5 keeps the framed transport envelope compatible with the Phase 4
implementation: the 40-byte header, CRC32 trailer, HELLO/CAPABILITIES gate,
build identity fields, and 512-byte maximum payload are unchanged.

The schema-level changes are:

| Area | Phase 4 | Phase 5 |
|---|---|---|
| Protocol release | 4.1 | 4.2 |
| Schema version | 1 | 2 |
| CAPABILITIES payload | 14 bytes | 20 bytes |
| Scope configuration | legacy `SCOPE_RECORD` stream | `SCOPE_CONFIG` (11), `SCOPE_ARM` (12), `SCOPE_STATUS` (13), `SCOPE_DATA_BATCH` (14), `SCOPE_STOP` (15) |
| Scope batch | not defined | fixed header with capture ID, firmware sequence/timestamp, channel IDs, sample flags and bounded raw values |
| Scope limits | not advertised | max 8 channels, 64 pre-samples, 128 post-samples, 6 samples per batch |

`SCOPE_ARM` uses an explicit action byte: `0=STOP`, `1=ARM`, and `2=MANUAL_TRIGGER`.
The action is diagnostic-only and does not enter the motor command path. The
old `SCOPE_RECORD` message remains decodable for compatibility, but the new
capture engine and UI use the 4.2 messages.

Compatibility policy:

- A 4.1/schema-1 peer is rejected at the HELLO/CAPABILITIES boundary; the host
  does not guess how to decode a Scope payload from an unknown schema.
- Build ID and manifest identity must remain stable for the lifetime of a
  decoded session.
- The Python transport accepts fragmented, sticky and noisy input, but keeps
  a bounded parser buffer and bounded event/raw-capture storage.
- Raw binary and CSV export preserve firmware `control_sequence` and
  `timestamp_cycles`; host WebSocket arrival time is not used for waveform
  alignment.

The source of truth for the generated Scope channel IDs, wire types, limits,
units and display ranges is `docs/scope_channel_schema.json`. C++, Python and
TypeScript outputs are generated by `tools/generate_scope_schema.py` and are
checked by the Phase 5 static gate.
